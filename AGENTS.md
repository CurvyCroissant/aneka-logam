# Project guidance

- This is the frontend-only Aneka Logam company profile: Astro static output, TypeScript, plain CSS, small vanilla JS enhancements, and Cloudflare Workers Static Assets. GitHub CI verifies; Cloudflare Git integration deploys.
- Use one main page per language, with native section links: Indonesian `/`, English `/en/`. Keep header navigation usable without JavaScript. Enhance language switching by updating translated text/metadata in the existing DOM without reloading images or replaying reveals. Preserve exact scroll pixels, expanded details, and gallery state; support Back/Forward. Keep the static language URLs usable without JavaScript.
- Preserve the supplied logo, Montserrat Bold company title, and #F5AA23 branding. Self-host fonts; no external asset requests.
- Keep content concise and give each section a distinct purpose. Location details belong only in the address. Center the footer's section navigation, contact actions, and copyright.
- Header/footer navigation labels are always Home, Products, Contact, including in Indonesian mode. Keep the primary navigation geometrically centered and more prominent than the language controls. All internal navigation, including language switches and error-page links, uses the current tab. Only external links open a new tab with noopener. The footer indicates the current section through color/background, without an underline.

- Company facts and official contact values belong in src/config/company.ts. The owner confirmed WhatsApp +62 813 8630 3535, telephone +62 21 6395 874, and anekalogaminfo@gmail.com. Do not assign numbers to individual people.
- Product information describes categories, not confirmed stock, material specifications, tolerances, or certifications. Do not invent company facts.
- Responsiveness is a continuing requirement at narrow, intermediate, tablet, landscape, and wide desktop dimensions, including enlarged text. Use intrinsic grids, wrapping, fluid type, visible keyboard focus, and touch targets. Never disable zoom or conceal layout problems with overflow masking.
- Use visible entrance, hover, and selected-state animation; honor reduced motion with non-spatial fades/color changes. Animate initially visible components on first load and refreshed/restored pages as well as first-time scroll entries. Keep reveal translation independent of hover transforms, and transition both into and out of interactive states. Leave content visible if scripts fail. Hover hints must work with keyboard focus and touch. Copy actions must report failure honestly and permit manual copying.
- Every content image, including both logos and placeholder illustrations, opens an image-only modal with a dark overlay. Animate from/to its source rectangle, fit within any viewport, close on outside click or Escape, and restore focus and scroll. Do not add visible viewer controls.
- Label the owners Pemilik/Owners; show Budiyanto and Delinah on separate rows with the requested male/female icons.
- Mask brand text with an animated skeleton until the self-hosted font is ready; use a bounded readable fallback on failure. Lazy-load noncritical images with reserved dimensions and visible-only skeleton animation. Fetch full-resolution viewer images only on demand.
- Use portrait/profile icons for the owners, not gender symbols. Keep the viewer borderless and suppress the residual focus ring on close while preserving regular keyboard focus indicators.
- Take scroll ownership in the external blocking head script, remove stale hashes for saved reloads, and keep manual restoration active. Do not wait for image downloads or run competing native/anchor restoration.
- Preserve scroll position on reload and history return, including expanded product details and gallery selection. Do not override fresh deep links or pull the page away after the user starts scrolling. Storage failures must fall back to native browser behavior.
- Keep dependencies and lockfile in sync. Run npm run verify after source/configuration changes. It checks behavior, generated links/metadata, performance budgets, and a Cloudflare dry run; it does not publish. Test real browser layouts when supported tooling is available and report any verification limits.
- The owner has not selected a domain. Never treat a suggested name as purchased or available. Keep indexing disabled until the agreed launch and real domain configuration.
- Do not add a backend, CMS, analytics, forms service, tracking, or external font dependency without a feature request. Keep credentials, business IDs, and .env out of commits.
- Recheck official legal sources before compliance advice. Static hosting is not automatically exempt from PSE or data-protection requirements.
